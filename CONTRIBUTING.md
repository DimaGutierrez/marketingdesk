# Cómo contribuir

Contanos primero qué trabajo intentás resolver, cómo lo hacés hoy y qué resultado esperás. Usá Discussions para propuestas y Issues para errores reproducibles. No adjuntes datos privados.

Para un cambio: fork, rama con nombre descriptivo, implementación pequeña, `npm test` y una pull request que explique el antes/después. Incluí capturas si cambia la interfaz. No agregues dependencias ni servicios pagos sin discutir su necesidad.

Son especialmente útiles las mejoras de accesibilidad, formatos CSV reales anonimizados, validaciones y reportes. Evitemos métricas de vanidad: una mejora se evalúa por el trabajo que permite completar.
